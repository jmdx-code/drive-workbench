# 综合网盘管理工具最终实施方案

确认日期：2026 年 10 月 20 日。产品名：云盘工作台。首版面向个人多 Gmail 的 Google Drive 文件与权限管理，以完整所有权交接和可配置批量权限操作为核心。

## 已确认范围

- 多 Gmail 账号独立管理，不提供全部账号聚合资源视图。
- 每个 Gmail 可导入多个 OAuth 客户端配置并分别授权，形成同身份并发池。客户端配置不是账号；通过 Drive about.user.permissionId 验证身份，错误身份不得进入池。
- 主动全盘或指定目录扫描，生成本次会话的本地目录树；本地展开、搜索、排序、选择、复制链接；文件大小和后代大小汇总；右侧集中操作。不要导航时逐目录重新请求 API，不做长期目录缓存或同步。
- 文件夹创建、重命名、同账号移动、普通文件云端复制、回收站及恢复。不提供永久删除。
- 协作者增删改查、批量添加、角色调整、精确替换和至少权限模式。支持全组合与逐行映射。
- 分享设置可组合：任何人链接、域/群组/用户授权、编辑者再分享、复制下载打印限制。默认保持，不自动全关。
- 批量转让所有权，由目标账号自动接收，逐文件验证，支持目录后代展开，默认保留原所有者编辑权限。
- 不实现上传下载、Sheets 内容编辑、双向同步、挂载、多厂商网盘和复杂日志平台。

## 四款参考审查结论

参考1的三份 Apps Script 已阅读，保留分页枚举后按 ID 组树、孤立项目归类和 HTML 快照交互；不复用先删除旧快照再创建新快照的顺序。文件夹列表只扫描两层；快照仅本人拥有项；批量删除无持久断点。

参考2的 manifest、后台、HTML、dashboard.js 已阅读，7z 包未解包。保留不同文件并行、实时进度、字段裁剪。其按 clientId 查重 token、每请求随机切身份、取消后仍输出全盘结论、吞异常、自动改父权限及移根目录不能复用。同账号多客户端池是本项目明确需求，必须先验证每连接真实身份。相关证据：dashboard.js 的 getNextAccessToken、scanAllOwnedFiles、closeSingleOwnedItem、636 行后的最终统计。

参考3深入检查 core、SheetService、权限对话框、目录 worker、命令与本地库；其他 Sheets 模块定向检查。单例 AuthManager 只有一个 token.json；AccountManager 实际是本地收藏库分组。权限接收行显示“待接收(所有者)”后被“所有者”过滤；sync_permissions 不更新已存在目标角色；部分扫描异常返回部分列表；404 被当永久删除；撤销使用当前 service；BaseCommand 导入和 self.sheets_api 引用有缺陷。保留目录筛选和批量选中流程，不沿用全局认证与大型 SheetService。源码 MIT，直接复用需保留声明；本项目采用新实现。

参考4完整追踪导出、授权、权限关闭、回收站与续跑。保留 actor 校验、逐项结果、删除前能力检查及恢复对账。ScriptProperties 与 Sheet 双状态不能原子提交，日志可被编辑，ScriptLock 限制吞吐，停止存在旧状态覆盖窗口。无跨账号所有权闭环。

四款均没有可靠的多 Gmail 发起转让、自动接收、最终验证闭环，也没有通用上传下载。参考1/2/4未见独立许可，首版不直接复制其代码。

## 产品交互

按用户最新指定方式：左侧只列 Google 账号，底部授权和设置；中间顶部为范围（全部/指定目录，另含回收站）、文件夹链接或 ID 和扫描按钮；下面直接显示扫描生成的可展开目录及大小。右侧集中分享、所有权转让、复制链接、重命名、移动、副本、删除/恢复、新建目录、链接导入、导出目录和任务记录。去掉大标题、统计卡片、重复的左侧目录树、常用位置导航和装饰页脚。任务记录通过右侧按钮弹出，不替换文件工作区。全选只选择当前过滤可见结果，后代范围在操作时明确选择。

批量操作流程：选择或导入 → 配置动作 → 展开并冻结具体对象 → 检查权限/所有权/类型 → 展示前后差异与阻塞项 → 提交任务 → 逐项执行和验证。账号切换不改变已提交任务身份。高危操作不自动扩大到父目录，也不自动移动文件。

分享面板：各设置默认保持。公开链接可开启 reader/commenter/writer 或关闭；用户、群组、域可单独添加/调整/删除；协作者替换先加新/改角色并验证，再删名单外直接用户。继承授权不能被当成直接授权删除。父级来源可查询并显式选中父目录另建任务；禁止失败后自动向上清理。批量角色可以精确设定，或只提升不降级。Google 不支持的组合由预检及接口返回明确阻塞。

## 技术架构

Electron + React + TypeScript + Vite；Node 内置 SQLite 保存任务，Electron safeStorage 保护 OAuth refresh token。单体本地应用，不引入 Python 服务、网络监听业务服务、微服务、Redis 或通用插件框架。生产界面不暴露 Node，开启 contextIsolation、sandbox，preload 只提供固定 IPC 方法，验证来源与输入。

目录：desktop 为 Electron 入口与 IPC；core 为领域、数据库、Drive、授权和执行器；src 为 React 界面；tests 为模拟接口与 UI 验证。依赖方向是 UI → IPC → Application → Engine/Drive/Store。UI 不持有真实 token。演示使用同一执行器与可丢弃的模拟数据，明确标示，不能假装为真实 Gmail。

## 账号和授权

支持批量导入 installed credentials 和 authorized_user token。同 client ID 的不同 Gmail 连接分属各自账号，不覆盖；一个账号多个 client 可并存。标准系统浏览器 OAuth，随机 loopback 端口，仅监听 127.0.0.1，PKCE S256 和 state 校验，授权超时清理。refresh 单次合并；刷新后验证身份，错误身份使连接失效。凭据加密不可用时不落盘明文并报错。scope 使用 drive；公开分发需自行配置并验证 OAuth 项目，不沿用参考中的内置客户端。

## 请求与并发

每任务固定源/目标账号。连接池仅选择同身份连接；全局、账号、连接并发可配置。不同文件并行，同 provider+fileId 写操作串行，转让的两身份步骤也共享该文件锁。403 rateLimitExceeded/userRateLimitExceeded、429 和可重试5xx指数退避加随机抖动；连接冷却，永久认证错误等待重新授权，网络写超时记结果未知先对账。不得把多凭据解释为无限绕过配额。父目录权限变更属于独立显式动作。

## 所有权转让

预检源 ownedByMe、非共享盘、非回收站、目标不同且已授权。源账号 permissions.create/update writer+pendingOwner；目标账号查询自己的权限并 update owner+transferOwnership；从目标视角 files.get 验证 ownedByMe/owners。原账号降为 writer，默认保留，可在验证后选择移除。发起/接收网络结果未知时查询远端，不盲目重复。已由目标拥有则记已满足。目标重新授权后从当前步骤继续。目录展开把每个后代冻结为项目，深层先于父目录；扫描不完整禁止提交该批次。不能声称目录转让自动包含后代。

## 数据与恢复

SQLite 将冻结计划与任务头保存在 records，项目结果保存在 task_items，记录固定账号、fileId、检查快照、尝试次数与实际结果。每次只事务更新变动项目和小型状态，避免每完成一项重写整批任务。界面轮询只读取摘要，打开明细才加载项目。状态包含 queued/running/succeeded/failed/unknown/cancelled/waiting_auth。启动时把中断 running 转为 unknown，手动继续先远端对账。暂停不领取新项，并在权限子步骤之间检查停止；在途请求完成并写回。失败重试仅重置失败/等待项，完成项保持。目录仅为当前会话的内存快照，每个账号保留最后一次扫描，退出后释放，不在 SQLite 保存目录。TanStack Virtual 只渲染可见行；任务和凭据持久化仍为安全恢复所必需。

扫描由用户明确触发：全盘使用 files.list 的全局分页，不对每个目录分别读取；指定目录读取全部子树。按 parents 在本地建立目录索引，展开、搜索、排序、导航和普通选择不请求 Drive。失败保留上次目录并提示，incompleteSearch 明确标注不完整。第一页不发送 pageToken，令牌失效只允许从头重读一次，丢弃旧页并去重，防止无限重试。文件列表扫描同时获取内联权限并展示邮箱与角色，缺失时明确提示；用户显式刷新权限时读取全部权限分页；写入预检和结果验证仍访问远端。文件夹大小按后代已知 size 求和，未知大小单列，不把配额占用等同文件大小。共享盘支持浏览，以能力字段决定动作；首版所有权转让排除共享盘。快捷方式操作自身、不自动跟随。404 表达不存在或无访问，不能判断永久删除。

## 文件操作

创建、复制的未知结果通过预生成 ID（接口支持类型）或 appProperties 任务关联标记对账，不能只按同名查找。移动/重命名/回收站/恢复按目标状态对账。移动检查目标为可访问非回收站目录、源父级未改变、目标不在源后代；不覆盖同名。文件夹复制不冒充 API 单请求能力。回收站父子重叠选择去重。HTML 快照本地导出，文本转义、无远程代码，提供目录折叠、过滤、选择及复制链接。

## 实施顺序与验收

先落地全部主要能力，再统一构建和验收，不把主要功能留为占位：
1. 账号、多客户端、实际身份验证、隔离演示。
2. 文件浏览/树/选择/导入/快照和文件操作。
3. 可组合权限和协作者完整替换。
4. 双账号所有权发起、接收、复核、恢复。
5. 并发、断点、停止、失败重试。
6. 类型检查、模拟接口测试、UI走查、生产构建与 Windows 包。

测试必须覆盖同client多账号不覆盖、不同文件并发/同文件互斥、替换先加后删、认证错误、限流、写入未知对账、转让发起/接收中断、目录范围、停止后无新项、重启恢复、不完整扫描、XSS及CSV公式防护。真实 API 测试必须使用专用可丢弃文件；用户未提供已授权账号时，自动完成模拟和界面验证并记录尚未执行的真实验证，不能声称已证明生产接口可用。

## 防止复杂度失控

独立复审已移除聚合、上传下载、Sheets 内容处理及动态插件架构。SQLite 是任务唯一事实来源，UI不另存执行状态。只给高风险网络写入做对账，不建设全套事件溯源；不提供万能撤销。首版只对 Google Drive 设计，不用未来多云需求制造层层适配。

## 1.1 用户纠偏后的实现与取舍

移除界面装饰和重复导航，将操作空间交还目录。实现仅围绕主动扫描和本地树操作，不添加长期缓存、自动同步、额外兼容流程。目录导出复用当前扫描；已验证的写入结果更新本次目录，不再全盘刷新。文件夹大小只累计扫描可见内容，不承诺不可见项目的真实总量。同账号多个不同 OAuth 客户端授权已接入同身份并发池；同客户端同账号的重复导入更新连接，不伪装成额外额度。Google 用户和项目配额仍然有效。

官方分页依据：https://developers.google.com/workspace/drive/api/reference/rest/v3/files/list 。本轮使用隔离演示配置和模拟 REST 验证，没有读取现有真实账号凭据或改动真实 Drive 文件。

## 参考1/2重新复审后的补齐

采用文件夹后代数量徽标、创建时间列、路径和名称直达、不可见父目录项目独立归组、准确的可见选择、隐藏选中提示、大小与存储占用分列口径。扫描时获取并展示邮箱和角色，可本地搜索授权邮箱；缺失权限不冒充私密。扫描显示页数/项数。目录可导出含权限的交互 HTML 或完整 CSV，保持当前简洁布局。完整证据和采用结果见《参考1与参考2交互复审及采用清单》。

当前编译交付固定为 `本地测试/云盘工作台.exe`，通过 `npm run build:local` 更新，不自动压缩或分发。

## 目录点击与可读性校正

按参考1截图：目录主要文字为16px，使用彩色分类图标和更清晰的文字对比度；单击文件夹行、图标或名称默认展开/收起，复选框负责选择。顶部两行显示文件/文件夹数量、汇总大小、未知项、扫描时间与存储占用。列顺序为名称、大小、创建时间、修改时间、所有者、邮箱权限。统计基于整个本次目录，不随折叠和搜索改变；虚拟未分类分组不计为真实文件夹。导出HTML同步提供汇总、彩色图标和更大文字。验证截图为test-results/10-readable-directory.png与11-readable-compact.png。

## 表格宽度与权限密度

名称、大小、创建时间、修改时间、所有者、邮箱权限六列提供拖拽分隔线；调整只改变目标列，必要时表格横向滚动，双击恢复默认，支持方向键微调。仅保存列宽偏好，重启恢复，不改变数据扫描机制。权限列表最高40px，超过范围格内滚动并显示项数，保留全部记录和可复制文本；权限区域操作不触发目录展开或框选。导出HTML也限制权限区域高度，CSV保持完整内容。

## 权限优先与目录密度调整

右侧直接展示批量添加邮箱、修改已有角色、移除指定邮箱、替换名单及链接/群组/域/限制设置。用户不必先理解通用“分享设置”的组合选项；每个入口预设相应选项，保留预览和组合配置。只修改模式通过权限规划器过滤不存在的主体，不创建新授权；仍保护所有者与继承权限。移除模式隐藏无关的角色、通知和至少权限选项。

主表保留16px文字，单行文件名、紧凑统计、34px普通行，权限最多两行滚动，拖动列宽不发起Drive请求。重复的大小/占用不再分行；不同或未知仍分别表达。低频新建文件夹置于折叠“更多文件操作”，所选文件详情折叠，权限明细限高。保持单次扫描、本地浏览模式，不引入新的目录缓存层。

## 所有者与任务导向交互修订

所有者从类型筛选拆出，默认全部；与搜索、类型条件叠加，单独所有者列可调宽。切换所有者清空选择，递归预览保持该所有者范围，并在冻结计划中记录该条件，执行时核查。未知与他人分别表达，不把权限明细缺失当作本人所有。文件夹自身操作可能影响继承或结构，筛选不承诺隔离Google的目录语义。

权限操作采用专用表单，固定其动作，只显示该动作必填字段和后果说明，再进入逐文件预览与确认。高级组合表单单独保留，确保主要功能不缩水，而常用操作不暴露无关选项。所有者移出权限列以压缩行高；旧列宽偏好保留，新所有者列使用默认宽度。

## 目录完整性与处理范围的显示

所有者筛选严格控制显示，默认全部；选择本人、他人或未知时，展开目录也不夹带范围外的后代。文件夹计数随所有者范围变化，未匹配的空未分类分组隐藏。移除“仅查看”上下文行。可见文件均可选择用于复制链接；每行提供无需选择的直接复制按钮，真实修改能力仍在任务预览与执行中核验。

表格填满可用宽度，剩余空间给名称或邮箱列；保留手动列宽、窄窗口横向滚动和恢复自适应入口。未分类分组与普通行保持八列一致。

## 按需限定扫描层级

扫描栏“最大扫描层级”默认关闭。开启后激活默认1的整数输入框；1读取指定目录直接子项，2再向下一层。全部文件在限层模式下从根目录起算，回收站不应用目录层级。限层使用逐层分页遍历，全量仍使用原有高效全局扫描。边界文件夹明确显示下级未扫描，未知大小不计为零；统计和导出只表达已扫描范围。此开关仅控制浏览目录生成，任务递归范围继续由任务表单独立预览确认。

框选文件与原生文字拖选互斥；空列表不创建选择框，拖动框限定在目录内容内，并在抬起、取消、失焦时清理。输入框与权限明细保留文字复制能力。

## 写操作入口权限边界

统一使用core/access.ts的小型纯函数判断操作能力，覆盖右侧按钮、右键菜单、表单打开前实时预检与后端预览/执行。转让所有权要求本人所有；其余操作使用Google实际capabilities，避免把编辑者合法操作一概禁止。混合批次有不支持项时整批禁用并说明原因，不自动忽略。未知能力需显式刷新，不能当作有权限。允许的入口先读取最新元数据，再打开专用表单；确认时重新生成实时计划，执行前再校验能力和目标目录。复制链接与本地导出保持可用。
