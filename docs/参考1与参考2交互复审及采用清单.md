# 参考1、参考2交互复审与采用清单

日期：2026-10-20。此次重点是重新沿着数据获取、生成页面、选择交互、权限呈现和导出链路检查，补足此前只借鉴树形结构、没有充分借鉴信息展示的不足。原参考源码未修改。

## 参考1：生成的 HTML 实际包含什么

证据来自 `参考1-脚本/网盘快照.txt`：`main`、`getHtmlHeader`、`getFooterScript`、`fetchOwnedItems`、`buildFileTree`、`calculateStats`、`generateHtmlFromTree`。

它先分页读取本人拥有项，再按 ID/父 ID 组树，递归汇总非文件夹数量与存储占用。输出是独立 HTML：名称链接、文件夹后代数量徽标、大小、创建日期、修改日期、层级缩进、共享目录或未分类组、固定表头、常驻选择/复制控制、生成时间、脚本被预览器禁用时的提示，以及跟随系统的深色样式。

真正有价值的不只是“有一个目录树”，还包括以下完整操作语义：

- 目录标题与目录内容分别处理：目录折叠后，目录自身仍能选择，内部项目不可被“全选可见”选中。
- 展开和勾选互不干扰；名称本身是打开 Drive 的链接。
- 文件夹直接显示后代文件数量和汇总量，减少逐层打开查看的次数。
- 找不到父目录的项目不会丢失，会进入独立的共享/未分类组。
- 勾选状态跨折叠保留，复制包含所选的隐藏项目；智能清空可以清除隐藏选择。
- 整个页面是一次获取后的本地交互，展开和选择不调用网盘接口。

原脚本的“大小”实际上来自 `quotaBytesUsed`，并把缺失值当作零；`calculateStats` 的数量统计不含文件夹。`generateHtmlFromTree` 按名称跳过快照文件，但统计在跳过之前完成，可能使统计和可见条目不一致。新工具保留准确的统计口径，不照搬这些含混之处。

## 参考2：权限为什么能直接显示

证据来自 `参考2-插件/dashboard.js`：`scanAllOwnedFiles`、`formatPermissionsSummary`、`hasTargetPermission`、`resolveItemPath`、`renderTable` 以及 `btnExportReport` 的事件处理。

`scanAllOwnedFiles` 在 `files.list` 的字段中直接请求 `permissions(id,type,role,emailAddress,domain,displayName,deleted,permissionDetails)`，而不是点击一行后才逐文件请求权限。扫描每页给出页数和累计项数；扫描完重新解析路径，避免父目录晚于子项返回时路径不全。表格把文件、路径、所有者和授权对象/角色放在同一行。界面只渲染前 500 项，但 CSV 使用全部 `lastScannedItems`。

这项优点应吸收为“扫描时一起取得可见权限并随目录展示”。不能照搬其状态结论：当未勾选移除协作者时，`hasTargetPermission` 忽略普通协作者，`formatPermissionsSummary` 却可能显示“仅本人私密”，这一表述不准确。也不能把缺失权限字段当作无共享。

Drive 的内联 `permissions` 仅在请求者能分享文件时提供，共享云端硬盘项目不提供该字段；没有这些数据时显示“未提供权限明细”，用户可明确刷新选中项。不会为兼容缺失字段而暗中给全部文件追加逐项权限请求。[Google files 字段说明](https://developers.google.com/workspace/drive/api/reference/rest/v3/files)

## 采用结果

| 参考优点 | 在当前工具中的采用方式 | 对应实现 |
|---|---|---|
| 一次读取，本地组树 | 保留主动扫描；展开、搜索、排序、选择不重新请求 Drive | `core/drive.ts`、`core/directory.ts`、`src/App.tsx` |
| 文件夹后代数量 | 名称旁直接显示非文件夹后代数量，详情另列子文件夹数 | `directoryIndex`、文件表格 `folder-count` |
| 大小与汇总 | 累计已知 `size`，未知项单列；同时单独显示 `quotaBytesUsed` 占用，避免混淆 | `DirectorySize`、`quotaSizeLabel` |
| 创建、修改时间 | 两列直接显示完整日期并可排序，详情也显示 | `FileEntry.createdTime`、文件表格 |
| 路径和名称直达 | 文件名称直接打开 Google 文件；文件夹名称和行默认展开；悬停及搜索结果显示本地解析路径 | `directoryPath`、`fileLink` |
| 共享/未分类组 | 扫描取得根目录 ID；父目录不在结果中的项目独立归组，虚拟组不能被提交为真实文件 | `ORPHAN_NODE`、`selectableVisible` |
| 折叠选择准确 | 折叠目录自身可选、后代不被全选；显示隐藏选中数；清空包含隐藏项 | 主界面选择逻辑、HTML 的逐层可见性检查 |
| 固定控制与表头 | 主界面操作台和表头常驻；导出 HTML 的控制栏与表头固定 | `src/layout.css`、`snapshotHtml` |
| 扫描时直接显示授权 | 同次列表响应读取权限，逐行显示完整邮箱和角色、公开链接、域/群组、待接收/继承状态 | `core/drive.ts`、`permissionRows` |
| 权限定位 | 在已有目录中按授权邮箱搜索，筛选外部授权或未提供明细的项目 | 主界面搜索与类型筛选控件 |
| 扫描反馈 | 在读取提示中显示已读页数和项数，不增加统计卡片 | `ScanProgress`、固定 IPC 事件 |
| 完整报告 | 现有“导出本次目录”可选择交互 HTML 或全部明细 CSV，均复用本次数据 | `snapshotHtml`、`snapshotCsv`、`exportSnapshot` |
| HTML 离线可用 | 创建/修改日期、后代数量、大小/占用、权限均保留；邮箱搜索、展开/收起、智能选择、批量复制 | `core/snapshot.ts` |
| HTML 适配实际使用 | 预览禁用脚本时保留提示、支持系统深色模式、复制失败反馈、名称与属性转义 | `core/snapshot.ts` |
| 多凭据操作便利 | 保留多文件导入、同身份连接池；授权窗口增加“依次授权未连接项”，每个客户端仍由用户在 Google 页面确认账号 | 连接对话框、`AuthService` |
| 操作后结果可核对 | 已完成分享任务使用实际验证的权限结果回填目录，不保留旧的邮箱角色 | `TaskEngine.execute`、任务结果回填 |

CSV 不限前 500 项，包含 ID、完整路径、已知字节数和未知项数、创建修改时间、所有者、全部可见授权及链接；对可能被表格当作公式的文本做防护。存储占用可能包含历史保留版本，不能拿来冒充文件大小。[Google quotaBytesUsed 说明](https://developers.google.com/workspace/drive/api/reference/rest/v3/files)

## 按当前需求取舍

保留左侧账号、中间扫描目录、右侧操作的结构，不恢复大标题、统计卡片、重复目录导航和大日志面板。跟随深色模式目前只应用于独立 HTML，不为此引入完整主题设置系统。

不采用参考2自动修改父级权限、自动脱离目录或移动根目录的操作；不采用“绝对私密”“不受限并发”等不可靠结论。不增加长期目录缓存、实时同步、多云适配或新框架。共享访问的真实范围可能受群组、继承和平台策略影响，表格呈现的是扫描时 API 提供的授权记录。

## 验证与本地测试方式

- 单元测试：目录汇总、占用与大小分离、孤立项目、权限缺失、HTML 转义、CSV 公式防护、分页和内联字段、扫描进度，以及原有授权/执行器回归。
- Electron 交互验证：账号切换、分享、所有权交接、创建/重命名/移动、回收站与恢复；浏览不重新读 API。
- 专项验证：折叠目录自身与隐藏后代选择、孤立项目归组、邮箱搜索、HTML 智能清空、隐藏选择提示、搜索后恢复折叠、按行复制链接、CSV 经 IPC 导出、本地 exe 启动。
- 使用独立临时用户目录与演示数据，未访问真实 Gmail 或操作真实网盘。结果在 `test-results/ui-results.json`、`test-results/reference-results.json`。

当前只运行 `npm run build:local`，更新固定的 `本地测试/云盘工作台.exe` 及其运行文件，不执行压缩或分发。后续更新仍使用这一位置；关闭旧程序后启动它即可测试。源码测试另可使用 `npm start`。

## 按截图进一步校正可读性

目录使用醒目的彩色分类图标，覆盖文件夹、表格、文档、PDF、图片、视频、音频、压缩包和快捷方式。普通单击文件夹行或名称只负责展开/收起，复选框负责选择；勾选不会改变展开状态。顶部用两行呈现文件/目录总数、已知大小与未知数、扫描时间和存储占用，不恢复装饰卡片。主要目录文字 16px，加深颜色和字重，辅助信息 13–14px；列顺序为名称、大小、创建、修改、邮箱权限。导出 HTML 同步扩大字号、增加图标和汇总。专项 UI 测试验证点击语义、图标、统计稳定性和实际计算字号。
