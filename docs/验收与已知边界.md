## 数据和权限的准确边界

目录是本次会话的扫描结果，退出即释放，不做持久目录缓存或自动同步。实际操作仍实时核验相关文件，完成后将已验证结果回填目录。外部客户端后续修改需要重新扫描才能完整更新。

`size` 与 `quotaBytesUsed` 分别作为内容大小和存储占用展示；文件夹累计扫描到的后代。缺失数据单列未知，不当作零。占用可能包含保留版本，不等于当前内容大小。

内联权限只显示 Google 实际返回的授权对象和角色。能分享的个人网盘文件通常可取得；共享盘和无分享权限等情况下可能不提供，界面明确显示未提供，用户可显式刷新。没有外部记录不自动断言“绝对私密”；群组成员、继承和组织策略也不由这份列表完全展开。

## 已知功能边界

- 无上传下载、永久删除、Sheets 内容编辑、挂载、双向同步和全部账号聚合。
- 无文件夹递归复制；文件夹递归权限/所有权操作会先完整展开再逐项处理。
- 同一文件在本应用中串行写入，其他客户端同时修改仍可能冲突，不宣称 Google 跨请求事务。
- 不自动修改父目录权限、限制继承或移动文件来“关闭分享”。404 只表达不存在或无访问权限。
- 网络写入结果未知时先对账；无法确认的复制不会盲目再创建。
- 每批操作最多 2 万项，扫描超过 10 万项需缩小范围。
- 同 Gmail 多客户端并发已实现，仍受 Google 项目/用户配额和后台限流约束。用户须在每个 OAuth 授权页面确认正确的 Gmail。
- 关闭应用后任务不在后台继续。真实任务和连接保存于用户数据目录的 SQLite；中断写入重启后待对账。连接内容经 Windows 系统保护加密。

- 添加支持多邮箱粘贴、统一角色和逐文件映射。修改已有角色不会创建缺失的邮箱；移除指定主体不会清理其他邮箱或公开链接。替换名单先新增并验证，再删除名单外的直接用户；清空用户仍须在替换表单中明确选择。公开链接、群组、域和用户分别控制。
- 对照参考3的 permission_manager_dialog.py 与 services/sheet_service.py 实际实现吸收分项入口、多邮箱、角色修改、名单同步和限制设置。保留本项目的逐项验证，不采用参考3向父目录递归撤销来扩大操作范围。
- 保留16px目录字号，压缩扫描/统计/搜索工具栏；普通行约34px，双行权限约46px。权限列表高度上限由96px降为40px，全部记录保留并可内部滚动，长邮箱悬停显示完整内容，列宽仍可拖动。
- 大小与占用相同时不再重复两行；不同则同一行区分，完整占用信息在悬停与文件详情中查看。未知仍明确标识。文件名采用单行省略，完整路径可悬停查看。
- 新建文件夹、导入链接与导出目录收进“更多文件操作”；文件元数据折叠，详细权限列表单独限高，避免挤走权限工具。
- 更新主流程测试，实际执行隔离演示账号的添加、只修改已有角色、指定邮箱移除；同时回归转让、重命名、移动、回收站和导出。修复旧验收脚本仍等待已移除扫描时间位置的问题，改为读取顶部统计。

## 所有者筛选与专用权限表单

- 默认“所有者：全部”，独立提供“他人 / 全部 / 未知”，与名称、ID、邮箱搜索和文件类型筛选取交集，不额外调用Drive。所有者单独可调宽列展示，本人显示“我”并可悬停查看邮箱，其他人显示邮箱；权限列不再重复所有者。
- 切换所有者清空选择；任务完成后的所有者变更也会剔除已不符合范围的选择。未知信息不归为本人。递归预览按当前所有者范围排除文件并显示排除数量；执行时核查范围，避免预览后变更所有者导致越界。
- 筛选控制每项直接操作；父文件夹本身的改权、移动和回收仍可能通过继承或目录结构影响后代，不能把筛选当成Google目录继承的隔离机制。
- 十个常用权限入口使用专用表单：修改角色只填多邮箱与目标角色；移除邮箱只填邮箱；开启链接只选角色；关闭链接/群组/域只展示明确影响说明；两类限制只选允许或限制。仅选中文件夹才展示递归选项。
- 主体类型、逐文件映射、至少权限、清空名单、多项组合等高级配置保留在单独“高级组合设置”，不会塞进常用操作表单。
- 专项命令 npm run test:permissions；结果 test-results/owner-permission-results.json，截图13-owner-filter.png与14-simple-permission.png。覆盖默认范围、搜索交集、他人目录内本人文件、未知所有者、选择清理、十种专用表单和高级能力保留。48项单元测试包含递归排除与复制前所有者改变的阻断检查。

## 严格所有者筛选、复制链接与框选

默认显示全部；选择“我/他人/未知”后，目录、搜索结果和类型筛选均严格取所有者交集。移除原来夹带不匹配后代的“仅查看”行。文件夹文件计数按所有者范围显示，悬停仍可查看扫描总数；只有其他所有者文件的未分类分组不出现在本人范围。转让后在全部范围仍可见，选本人则隐藏。

所有可见项目都能勾选用于复制链接；真实查看权限不会阻止复制链接，修改权限仍由操作预览和Google实际能力核验。每行新增独立复制链接图标，无需勾选、不改变当前选择；保留右键复制与勾选后批量复制。

空列表不启动文件框选。框选开始阻止浏览器文字拖选，拖动时清除原生文字选区并把框限制在目录内容区域；抬起、取消或窗口失焦清理状态。邮箱明细及输入框仍支持正常文字复制。

列宽响应容器ResizeObserver，自动利用剩余空间并保留手动拖动、“自适应列宽”和窄窗口横向滚动。行操作列容纳复制和更多两个图标，固定宽度计算统一。

npm run test:context 验证隔离演示转让、默认全部、严格本人范围、文件计数、隐藏空分组、查看权限文件单独/批量复制、复制不改变选择、空目录拖动、框选不选中文字、不覆盖表头和窗口自适应。结果test-results/context-results.json，截图17-strict-owner-copy.png；未操作真实网盘。

## 最大扫描层级

扫描栏新增“最大扫描层级”复选框，默认关闭、扫描全部；开启时数字默认1，可输入1到1000的整数。层1为所指定目录的直接子项，层2再读取一层。全部文件的限层扫描以我的云端硬盘根目录为起点，不读取更深层或独立共享位置；未限层仍使用原来的全局分页扫描。回收站为平面列表，层级选项禁用。

后端按层遍历且每个目录完整分页，不是先全量扫描再过滤。达到层级边界的文件夹标注“未扫描/下级未扫描”，大小和占用未知向上汇总；统计说明只含已扫描部分，导出HTML/CSV保留未知边界。浏览和展开不额外请求API。权限任务的递归选项独立控制，勾选后仍完整扫描并冻结任务范围，不把目录浏览限层误当作权限操作限层。

npm run test:depth 检查默认状态、1层、2层、指定目录相对层级、边界提示、无效输入与关闭后全量扫描。52项单元测试包含实际HTTP查询与分页边界验证。测试使用隔离演示数据及模拟HTTP。

## 所有操作入口的权限校验

- 右侧与右键菜单共用core/access.ts规则：转让必须本人所有且可分享，排除快捷方式与共享盘；改权按canShare；重命名/移动/副本/删除/恢复分别按canRename/canMoveItemWithinDrive/canCopy/canTrash/canUntrash；查看者复制限制按canChangeCopyRequiresWriterPermission；个人盘编辑者再次分享设置要求所有者及编辑能力。新建、移动、复制另核验目标目录canAddChildren。
- 能力未知时不默认可写，按钮禁用并提示先刷新；多选中任一文件不符合条件则整批禁用，悬停显示数量、首个文件与原因，不静默缩小范围。非所有者编辑者仍可使用Google明确允许的操作，不按“非本人”一律禁止。
- 选中只使用本次目录元数据判断，不追加API读取。点击允许的修改入口后分批读取所选文件最新元数据，校验通过才打开表单；账号切换时丢弃结果。刷新操作权限可显式修复缺失或过期的能力信息，不读取整个目录。
- 操作预览逐项实时检查；执行前再次读取能力，移动/创建/复制还检查目标目录，转让流程检查源账号当前所有权及分享能力。已达到目标状态的恢复/删除等操作不为重复写入而越过幂等判断。服务端仍可能在请求间撤销权限，以实际API结果为准。
- 复制链接、导出、本地查看不要求修改权限，查看权限的文件仍能复制链接。

58项单元测试包含非所有者转让、编辑者合法操作、能力缺失、混合选择、专有设置与预览后撤权阻断。npm run test:access通过查看者/编辑者/所有者、菜单一致性、混合选择、实时撤销分享及所有权、未知权限刷新等UI检查，结果test-results/access-results.json，截图18-action-access.png。原有完整操作流程和专用表单测试通过。测试均为隔离演示或模拟请求，未操作真实账号。

## 转让后移至目标账号根目录（2026-10-20）
