# 1.3.0 验收记录

日期：2026-10-22。

本次完成 API 请求复用、所有权转让阶段恢复、统一限流和并发调整。未使用真实 Google 账号进行云端写入验收。

## 已实现

- 默认每账号 18、每授权连接 6，立即使用可用上限；单连接可用上限为 6。移除全局业务并发字段，旧全局设置忽略，旧超大账号/连接值限制到新上限，较低设置保留。
- 每个源账号独立调度，某账号等待网络或冷却不阻挡其他账号的新任务；所有请求仍经过共享连接池，单文件写入锁保留。
- 账号级限流统一作用于该邮箱全部连接，项目级限流统一作用于同项目连接；同一轮在途请求的错误只减半一次，最低为 1，遵守 Retry-After。冷却结束后稳定 60 秒逐级恢复。
- 新导入配置保存 project_id。缺少项目标识的历史连接按未知项目组保守退避，不将不同客户端误认为独立配额。运行中的降速和冷却不持久化到下次进程。
- 共享/每日配额限制不进行短时间反复写入；授权失效、权限拒绝和网络异常不一概当作普通限流。
- 转让阶段持久化邀请中、已邀请、接收中、已接收和已复核。正常路径直接使用邀请响应的权限 ID，最终读取目标所有权验证。同步延迟自动复查；未知邀请或接收结果先对账，不盲目重复发送邀请。
- 单次预览复用目录元数据，去除重叠的递归扫描。权限新增/更新复用前一步验证结果；删除、替换保留额外冲突检查。复制步骤复用同次执行的源文件读取。
- 任务保存执行阶段 Drive 读取、写入、重试/复查及限流响应计数；保存每项最近 40 条阶段、等待、错误与暂停事件。明细和 CSV 可查看，成功后仍保留此前原因。
- 设置页展示当前有效并发、在途请求、近一分钟请求量、冷却剩余时间及原因。历史未计数任务不伪造旧调用量；扫描、预览与 OAuth 令牌请求不计入任务执行统计。

## 可复现数据

基准通过真正的 GoogleDrive HTTP 请求封装，对接隔离内存响应计数，不发送远程请求。旧版本由 1.2.2 正式包提取的编译代码运行，新旧使用相同测试脚本。7 项模型包含 3 个文件夹、4 个文件、3 层目录，每次列表单页，不移动根目录、不清理原账号权限、不含 OAuth 刷新及底层网络重试。

| 场景 | 1.2.2 | 1.3.0 | 请求下降 |
|---|---:|---:|---:|
| 正常 7 项转让执行 | 49 | 35 | 28.6% |
| 正常 7 项从扫描到完成 | 59 | 44 | 25.4% |
| 每项首次目标权限列表不可见，执行阶段 | 77，暂停 3 次 | 35，暂停 0 次 | 54.5% |
| 父子目录同时选择的预览 | 8 | 5 | 37.5% |
| 单文件新增 3 个协作者 | 11 | 8 | 27.3% |
| 单文件新增 10 个协作者 | 32 | 22 | 31.25% |

新增更严格场景：每项第一次接收被明确拒绝，第一次目标权限读取也暂不可见。1.3.0 使用 56 次执行请求自动完成 7 项，暂停 0 次，没有重复发起邀请。它与上表旧版本场景的注入点不同，不计算跨场景节省比例。等待测试采用零延迟测试参数；表格不表示真实云端耗时提升，也不等于 Google 配额单位同比下降。

并发/退避实测使用真实墙钟、隔离 HTTP 响应：单账号单连接立即达到 6，单账号 3 连接达到 18，两账号 6 连接达到 36。服务器要求等待 2000ms 时，跨连接后续请求实际间隔 2059ms；两连接账号的上限由 12 降为 6。60 秒恢复、同轮去重、跨项目隔离另有可控时钟测试。
