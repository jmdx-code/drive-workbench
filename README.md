# 云盘工作台

个人多 Gmail 的 Google Drive 桌面管理工具。支持账号独立浏览、同账号多 OAuth 客户端并发、文件管理、可组合分享设置、协作者批量替换、所有权转让与目标自动接收。

## 正式版运行

当前版本为 **1.3.5**。从 [GitHub Releases](https://github.com/jmdx-code/drive-workbench/releases) 下载与你的系统匹配的便携 ZIP，完整解压后运行，无需安装。Windows 运行“云盘工作台.exe”；Mac Apple Silicon 选择 arm64，Intel 选择 x64，运行“云盘工作台.app”。不要从 ZIP 内直接运行。先退出旧版窗口再启动新版。

## 自动更新与自动构建

正式便携版启动后自动检查 GitHub 最新稳定版，先用固定公钥验证 Ed25519 清单签名，再下载对应平台 ZIP 并核对大小与 SHA256；缺失/无效签名不会安装。准备好后在左侧及设置中提示“重启更新”，由用户确认后替换程序并重新启动。账号、授权和任务位于独立用户目录，更新不会清空；执行中的任务须先暂停并等待请求结束。旧程序保留为同级 `backup` 目录，替换失败时恢复旧目录，日志位于用户目录 `updates/update.log`。开发模式及“本地测试”目录禁用自动更新。

Mac 目前采用 ad-hoc 签名，未通过 Apple Developer ID 签名及公证，首次打开可能被 Gatekeeper 拦截，需要在 macOS 系统设置的隐私与安全性中确认打开。后续若取得开发者证书，可增加正式签名和公证。

更新 `package.json` 和锁文件版本、推送源码后，在 GitHub 创建匹配标签的 Release 并发布。Actions 自动完成三平台测试、打包、签名与上传，无需下载后手工签署。仅需一次性配置受保护的 `release-signing` Environment 和 `UPDATE_SIGNING_PRIVATE_KEY` Secret。旧客户端首次迁移及配置步骤见 [发布说明](docs/构建与发布.md)。

正式运行默认使用真实账号；没有账号时显示导入配置与浏览器授权引导。已有账号、连接和任务沿用 Windows 用户数据目录，升级不清空。演示账号和模式切换仅在独立 `WB_QA_DIR` 测试配置下启用，不出现在日常界面。

`release/当前版本.json` 指向最新本地构建；最近的 1.3.1、1.3.2 便携版保留供回滚，早期构建和测试资料已移出工程。目录结构和整理边界见 [本地目录整理](docs/本地目录整理.md)。`本地测试/` 是开发运行目录，通过 `npm run build:local` 更新；`npm run package` 构建当前系统的正式便携包。测试、截图、参考项目、备份和开发依赖不放进交付包。

1.3.1 统一了程序文件、窗口、侧栏和网页图标，正式启动不再初始化演示数据。图标源文件与多尺寸 ICO 位于 `assets/branding/`，`npm run build` 自动生成运行用 PNG。开发清理记录见 `docs/清理与图标验收-1.3.1.md`。

## 连接真实 Gmail

1.3.2 新增本地数据与记录管理，以及真实账号头像。任务中心可删除单条记录、批量清理已结束任务；顶部可清空扫描，设置和账号授权窗口可进入“数据与记录管理”，移除账号或输入确认文字重置本地数据。执行中、仍有在途请求的任务不能清理。清理不删除 Drive 文件，也不撤销已完成的操作；删除暂停任务会失去继续与对账入口。

授权时从现有身份请求读取 `photoLink`；旧账号首次补取。头像转换为 96px PNG 存入本地 SQLite，缓存一天，过期在下次启动时更新；可手动刷新。没有头像或网络失败时显示首字母，已有缓存优先保留。无需追加 OAuth 权限。详情见 `docs/数据清理与头像验收-1.3.2.md`。

1. 在自己的 Google Cloud 项目启用 Google Drive API，配置 OAuth 同意屏幕。如果项目在测试状态，将要登录的 Gmail 加入测试用户。
2. 创建类型为 Desktop app 的 OAuth 客户端，下载 `credentials.json`。
3. 在应用“账号与授权”中点击“导入授权文件”。点击该连接的“浏览器授权”，在系统浏览器选择 Gmail 并同意 Drive 访问。
4. 可重复导入不同客户端配置并授权给同一个 Gmail，形成该账号的并发池。给其他 Gmail 授权时会创建独立账号，不覆盖已有身份。
5. 已有 authorized_user 类型 token.json 也可导入，应用会先刷新并验证身份，再加密保存。

OAuth 配置中的 client secret 在桌面应用中不是可保密的用户密码；真正需要保护的是用户 refresh token。本应用通过 Electron safeStorage 使用 Windows 系统保护或 macOS 钥匙串保存连接，不提供内置第三方 OAuth 客户端。

## 文件操作

左侧直接列出 Google 账号，底部是账号授权和设置。顶部选择“全部文件”或“指定目录”，粘贴文件夹链接/ID（root 为根目录），点击“扫描”。扫描读取全部分页及指定目录的后代，在内存中生成本次目录；展开、搜索、排序、选择、进入子目录及切换回已扫描账号均不重新请求 Drive。关闭应用后目录不保留；需要更新时手动再扫描。回收站通过顶部范围选择后扫描。Ctrl 多选、Shift 连选；全选只选择当前过滤可见项。

右侧是操作控制台，包含分享、所有权转让、复制链接、重命名、移动、副本、删除（移入回收站）、恢复、新建目录、链接导入和本次目录导出。扫描列表时同时读取可见权限，逐行显示邮箱和角色；可在右侧明确刷新。未提供权限时不会当作私密，也不暗中逐文件补查。任务执行前仍实时核验相关文件。已验证的创建、重命名、移动和删除结果直接更新本次目录，不能据此认为远端实时同步。复制不支持文件夹单请求复制；同名不会自动覆盖。导入链接可以批量验证和选择指定文件。目录导出直接使用本次扫描结果，不再扫描网盘，可选择独立交互 HTML 或完整 CSV。HTML 支持折叠、邮箱搜索、全选可见、清空隐藏选择和复制链接。名称旁显示文件夹后代文件数量，表格包含创建/修改时间及邮箱与权限。大小列同时列出内容大小和存储占用的各自汇总；Google 未提供大小的项目显示未知，不当作零。汇总仅代表本次扫描可见内容，空文件夹显示 0 B。

所有者筛选默认“全部”；选择“我”时，展开与搜索均严格只显示本人拥有的文件，文件夹计数随所有者范围变化。每行末尾链条图标可直接复制链接，无需选择；查看权限文件也能勾选后批量复制。文件框选不会同时拖选界面文字，空列表不启动框选。

## 分享与协作者

分享面板各项默认“保持”。可开关任何人链接访问，添加、调整、移除或替换协作者，单独处理群组和域授权，以及编辑者再分享和查看者复制/下载/打印限制。个人 Gmail 或具体文件不支持的设置会明确失败，不冒充成功。

输入多个邮箱默认应用到全部所选文件。勾选逐行映射时，每行格式为 `文件链接,邮箱,writer`，角色还可使用 reader、commenter；映射文件必须在选中范围内。替换先增加并验证新权限，再移除名单外直接用户授权，保留所有者。清空全部直接用户协作者有单独勾选项。至少权限模式不降低已有更高权限。

不自动删除父目录授权或移动文件来处理继承权限。修改父目录时请明确选择父目录另建操作。操作前生成冻结计划并展示被阻止项目，再由用户确认执行。

右侧修改按钮与右键菜单按所选文件的实际操作能力灰显，不可用时悬停查看原因；混合批次不静默跳过文件。点击允许的修改操作后重新校验权限，通过后才打开表单。能力缺失或已变化时可点击“刷新操作权限”。复制链接不要求修改权限。

## 所有权转让

连接源、目标 Gmail，选择文件或文件夹，打开“转让所有权”。可明确包含目录全部后代。应用发起转让，由目标账号自动接收并验证所有者；默认保留原账号编辑权限，可选择验证成功后移除原账号访问。Google 系统可能发送通知邮件。

可另行勾选“转让后移到目标账号的‘我的云端硬盘’根目录”，默认关闭。预览列出移动与权限影响；先验证本批项目的所有权，再由目标账号移动所选顶层项目，递归时保留内部层级，不把子文件打散。勾选移除原账号时，移动完成后从父到子重新读取并清理其直接权限；继承授权仍存在则明确报告，不擅自修改原父目录共享。所有权已成功而移动或权限清理失败时，结果和错误会保留具体完成阶段，可继续对账；旧任务不会自动启用新选项。

共享云端硬盘、快捷方式、非源账号所有或不可访问的对象会被阻止。目录和后代逐项处理，不把文件夹转让等同于后代全部转让。

## 并发与恢复

取消全局业务并发上限，每账号最高 18、每授权连接最高 6，默认即使用可用上限。不同账号独立调度；同一文件修改仍串行。账号或项目限流时统一减半并遵守 Retry-After，同轮报错只降一次；冷却结束后连续稳定 60 秒逐级恢复。未知项目归属的历史连接在项目级限流时保守共同退避。多客户端不代表可以绕过 Google 配额。

真实任务保存在应用用户数据目录的 SQLite 中。关闭应用后不会继续执行；下次启动原运行项目进入“待对账”并暂停。任务中心可继续/对账并导出 CSV。停止不再领取新项，但已发送的请求需要等待结果。结果未知的复制若无法查到关联对象，会停止并要求人工核查，避免重复创建。

## 源码运行

需要 Node.js 24 或兼容版本，Windows x64。首次执行 `npm ci`，若 Electron 二进制被安装脚本策略跳过，执行 `node node_modules/electron/install.js`。

```text
npm run build
npm start
npm test
npm run test:ui
npm run package
```

开发时先运行 `npm run dev`，另一个终端运行 `npm run desktop:dev`。构建和打包不会运行参考工具或修改网盘。

方案位于 `docs/综合网盘管理工具最终实施方案.md`。测试和真实账号验证边界见 `docs/验收与已知边界.md`。本项目不实现上传下载、Sheets 内容编辑、永久删除、全部账号聚合、同步或挂载。

详细采用依据与验证说明见 [参考1与参考2交互复审及采用清单](docs/参考1与参考2交互复审及采用清单.md)。

目录界面按参考1强化：彩色分类图标；单击文件夹行或名称展开/收起，复选框负责选择；顶部显示文件/文件夹总数、汇总大小和扫描时间；主要目录文字为 16px，辅助信息提高对比度。名称、大小、创建和修改时间直接排列，后方保留邮箱权限。

表头各内容列右侧可拖拽调整宽度，双击分隔线恢复该列默认值；列宽作为界面偏好保存，重启后保留。权限列表最多占96px高度，更多记录在单元格内滚动，显示总项数；点击/滚动权限区域不会展开目录，完整数据仍参与搜索与导出。

## 1.3.0 请求优化与统计

预览读取在单次操作内复用，父子目录同时选择时去除重叠扫描。转让保存邀请、接收与复核阶段，优先使用邀请返回的权限 ID；短暂传播延迟自动复查，未知写入先对账。权限添加/更新复用前一步验证结果，删除和替换仍保留额外冲突检查。任务卡片及 CSV 展示执行阶段的 Drive 请求统计，明细保留每项最近 40 条阶段、等待、限流及暂停事件。扫描、预览和 OAuth 令牌请求不计入任务执行计数；历史未计数任务不伪造历史调用量。

历史 API 请求对比保存在 `docs/benchmarks/api-1.3.0-comparison.json`，来自旧 1.2.2 与 1.3.0 编译代码的同一隔离 HTTP 数据。`node scripts/api-call-baseline.mjs` 可重新生成当前代码的请求计数；原始历史报告已随旧测试资料移出工程。
